1. Schnellstart

Öffentliche Basis: https://HOST/PFAD/easyITCalendar/api-v1.php. Alle Antworten sind JSON. Fremdanwendungen verwenden ausschließlich api-v1.php oder die öffentliche JavaScript-Klasse EasyITCalendarAPI.

JavaScript-Client: assets/js/easyit-calendar-api.js
PHP-Beispiele: docs/examples/php/
JavaScript-Beispiele: docs/examples/javascript/

Für PHP zuerst examples/php/_config.php.example nach _config.php kopieren und Basisadresse sowie Token eintragen. Die mitgelieferte _client.php kapselt cURL, JSON und HTTP-Fehler.

2. Authentifizierung und Rollen

Jeder Aufruf benötigt Authorization: Bearer <TOKEN>. Tokens werden in api-tokens.php erzeugt.

RolleRechte
viewerMetadaten, Events, Blockierungen, Kategorien und Places lesen
editorviewer + Events und Blockierungen anlegen, ändern, löschen
admineditor + Kategorien, Places und API-Tokens administrieren
Sicherheit: Ein dauerhaftes Token gehört nicht in öffentlich abrufbaren Browsercode. Für öffentliche Websites ein eigenes Backend/Proxy einsetzen.

4. Nutzdaten

Event

{
  "start": "2026-10-05T14:30:00",
  "end": "2026-10-05T15:30:00",
  "title": "Besprechung",
  "description": "Projektstatus",
  "location_id": 3
}

Ein Event, das eine aktive Blockierung überschneidet, wird mit HTTP 409 / TIME_BLOCKED abgewiesen.

Blockierung

person_id leer, 0 oder nicht gesetzt bedeutet: Die Blockierung gilt für alle Personen. Eine positive ID begrenzt die Sperre auf diese Person.

{"start":"2026-10-06T08:00:00","end":"2026-10-06T10:00:00","category_id":2,"person_id":0,"reason":"Nicht verfügbar"}

Kategorie

{"name":"Intern","description":"Interne Sperrzeit","activ":1}

Place

Unterstützte Felder: name, description, address, street, postal_code, city, country, room, activ.

5. Kalenderansichts-API: render(filterObjekt)

Die Kalenderansicht wird über window.TinyCalendar gesteuert. Der verbindliche Einstieg lautet TinyCalendar.render(filterObjekt).

Ungefilterter Zustand: TinyCalendar.render(null) zeigt alle für den sichtbaren Zeitraum geladenen Termine. null ist der definierte Zustand „kein Filter“.

Nach einem Feld filtern

TinyCalendar.render({ category_id: 3 });

Mehrere Felder

TinyCalendar.render({
  to_student: 17,
  activ: true,
  category_id: 3
});

Mehrere Felder werden mit UND verknüpft. Arrays erlauben mehrere zulässige Werte:

TinyCalendar.render({
  event_status: ['planned', 'confirmed']
});

Operatorfilter

TinyCalendar.render({ thema: { contains: 'Mathematik' } });
TinyCalendar.render({
  start: { gte: '2026-10-10T08:00:00', lt: '2026-10-10T12:00:00' }
});

Unterstützt werden eq, neq, in, contains, startsWith, endsWith, gt, gte, lt, lte, between und empty.

Aktiven Filter lesen oder zurücksetzen

const filter = TinyCalendar.getFilter();
TinyCalendar.render(null);

Filterbar sind alle normalisierten Terminwerte sowie sämtliche vom Server in filter_data gelieferten DataForm-Felder. Dadurch funktionieren auch projektspezifische Calendar-Felder ohne Änderung der Render-API.

6. Personenbezogene Blockierungen

Eine Blockierung kann über person_id genau einer Person zugeordnet werden. Ist person_id leer, 0 oder null, gilt sie für Alle Personen. Gleichzeitige Blockierungen verschiedener Personen bleiben getrennte Datensätze.

{
  "start":"2026-10-10T08:00:00",
  "end":"2026-10-10T10:00:00",
  "category_id":2,
  "person_id":17,
  "reason":"Nicht verfügbar"
}
