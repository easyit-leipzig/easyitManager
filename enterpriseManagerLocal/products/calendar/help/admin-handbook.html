1. Ziel und Zuständigkeit

Dieses Handbuch richtet sich an Administratoren, die den Kalender installieren, konfigurieren, freigeben und warten. Die Tabelle main_settings bildet die zentrale Quelle für globale Kalendereinstellungen. Die Datei init.json ist die Initialisierung, die der Browser beim Start tatsächlich lädt.

Grundsatz: Die Datenbank ist die administrative Quelle. Die für einen konkreten Benutzer ausgelieferte init.json oder API-Antwort ist das daraus abgeleitete Laufzeitprofil.

2. Installation der Einstellungstabelle

  1. Datenbank in phpMyAdmin oder einem SQL-Client auswählen.
  2. Die Datei sql/main_settings.sql importieren.
  3. Prüfen, ob die Tabelle main_settings angelegt wurde.
  4. Die Kontrollabfrage am Ende des Skripts ausführen.
  5. Den Kalender zunächst mit den mitgelieferten Standardwerten testen.
SELECT COUNT(*) AS settings_count FROM main_settings;
SELECT * FROM main_settings ORDER BY setting_group, setting_key;

Das SQL-Skript kann erneut importiert werden. Vorhandene Schlüssel werden über den eindeutigen Schlüssel aus Gruppe und Name aktualisiert, aber nicht doppelt angelegt.

6. Rechteverwaltung

Rechte beantworten die Frage: Darf der angemeldete Benutzer diese Aktion ausführen? Funktionsschalter beantworten dagegen: Ist diese Funktion in der Installation technisch aktiviert?

lesson_editTexte, Zuordnungen und Zeiten bearbeitenTermin muss lesbar sein.
lesson_deleteTermine entfernenLöschschaltfläche ausblenden und serverseitig prüfen.

Sicherheit: Ein ausgeblendeter Button ist kein Zugriffsschutz. Eine spätere PHP-API muss jedes Recht erneut serverseitig prüfen.

7. Ansichten administrieren

Mindestens eine Ansicht muss aktiv sein. Die Standardansicht muss zugleich freigeschaltet sein.

UPDATE main_settings
SET setting_value='month'
WHERE setting_group='calendar' AND setting_key='default_view';

UPDATE main_settings
SET setting_value='false'
WHERE setting_group='views' AND setting_key IN ('day','week');
  • Tagesansicht: voller Funktionsumfang eines einzelnen Tages.
  • Wochenansicht: voller Funktionsumfang über sieben Tage.
  • Monatsansicht: reine Darstellung aller Termine, ohne Drag-and-drop.

9. Einstellungen sicher pflegen

Einzelwert ändern

UPDATE main_settings
SET setting_value='5'
WHERE setting_group='calendar'
  AND setting_key='snap_radius_px'
  AND editable=1;

Wert lesen

SELECT setting_value, value_type
FROM main_settings
WHERE setting_group='calendar' AND setting_key='slot_minutes';

Neuen Schlüssel ergänzen

INSERT INTO main_settings
(setting_group, setting_key, setting_value, value_type, description)
VALUES ('calendar','show_slot_labels','true','boolean','Zeitbeschriftung je Slot anzeigen.');

Empfehlung: Änderungen zunächst in einer Testinstallation vornehmen, danach die Kalenderansichten und die Browserkonsole prüfen.

10. Validierungsregeln

  • slot_minutes muss größer als 0 sein und sinnvollerweise 60 ohne Rest teilen.
  • hour_start muss kleiner als hour_end sein.
  • snap_radius_px darf nicht negativ sein; Projektstandard ist 5.
  • default_view muss day, week oder month sein.
  • Mindestens eine der drei Ansichten muss aktiv sein.
  • JSON-Werte müssen mit JSON_VALID(setting_value) geprüft werden.
  • Farben sollten gültige CSS-Farbwerte sein.
SELECT setting_group, setting_key, setting_value
FROM main_settings
WHERE value_type='json' AND JSON_VALID(setting_value)=0;

11. Von main_settings zur init.json

Der aktuelle Kalender lädt eine statische init.json. Für einen produktiven Betrieb sollte ein PHP-Endpunkt die Datenbankwerte lesen, typisieren und als JSON ausgeben.

  1. Alle globalen Werte aus main_settings lesen.
  2. Werte anhand von value_type in int, float, bool oder JSON umwandeln.
  3. Schlüssel nach setting_group zu verschachtelten Objekten gruppieren.
  4. Rollen- und Benutzerrechte darüberlegen.
  5. Nur die für den angemeldeten Benutzer gültige Konfiguration ausliefern.
{
  "views": { "default": "week", "day": true, "week": true, "month": true },
  "rights": { "lesson_read": true, "lesson_move": true },
  "features": { "drag_drop": true, "overlaps": true },
  "calendar": { "slot_minutes": 30, "snap_radius_px": 5 }
}

12. Empfohlene Rollenprofile

Administrator

Alle Ansichten, Rechte und Funktionen aktiviert. Löschen und Blockieren erlaubt.

Tutor

Termine lesen, anlegen, bearbeiten und verschieben; Löschrecht optional. Tages- und Wochenansicht aktiviert.

Student

Termine lesen; Monats-, Wochen- oder Tagesansicht nach Bedarf. Keine Änderungen und keine Blockierungsverwaltung.

Informationsanzeige

Nur Monatsansicht und lesson_read; alle Bearbeitungsrechte deaktiviert.

13. Sicherung, Export und Rücksetzung

Sicherung

mysqldump -u root -p datenbank main_settings > main_settings_backup.sql

CSV- oder JSON-Export

Vor größeren Änderungen sollte zusätzlich ein Export über phpMyAdmin erzeugt werden. Die Felder setting_group, setting_key, setting_value und value_type müssen erhalten bleiben.

Standardwerte wiederherstellen

Das mitgelieferte Skript sql/main_settings.sql erneut ausführen. Durch ON DUPLICATE KEY UPDATE werden die enthaltenen Standards wieder eingesetzt.

15. Sicherheit und produktiver Betrieb

  • Adminseiten nur nach Session-Login bereitstellen.
  • Änderungen mit CSRF-Token absichern.
  • Prepared Statements für alle Datenbankzugriffe verwenden.
  • Gruppen und Schlüssel serverseitig über Positivlisten prüfen.
  • Rohes JSON vor dem Speichern validieren.
  • Rechte bei jeder API-Aktion erneut prüfen.
  • Änderungen an Einstellungen in einer Audit-Tabelle protokollieren.
  • Die Datenbankzugangsdaten niemals in JavaScript oder init.json ablegen.

17. Häufige Fragen

Warum gibt es main_settings und init.json?

main_settings ist die zentrale administrative Datenquelle. init.json ist die konkrete Laufzeitkonfiguration für den Browser.

Darf ich neue Einstellungsgruppen anlegen?

Ja. Der Loader oder die Adminoberfläche muss die neue Gruppe jedoch kennen und validieren.

Kann eine Rolle eigene Einstellungen erhalten?

Ja. Dafür sollte später eine separate Tabelle für Rollenüberschreibungen ergänzt werden, statt globale Werte in main_settings mehrfach anzulegen.

Warum werden Booleans als Text gespeichert?

Die Tabelle verwendet einen einheitlichen Textspeicher. value_type legt fest, wie der Loader den Rohwert typisiert.

Ist die Monatsansicht bearbeitbar?

Nein. Sie ist absichtlich eine reine Darstellungsansicht.
