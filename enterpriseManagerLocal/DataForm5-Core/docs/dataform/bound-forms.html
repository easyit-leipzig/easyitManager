Gebundene Formulare

Ein gebundenes Formular stellt Kinddatensätze zu einem aktuellen Hauptdatensatz dar. Der Schlüssel des Hauptdatensatzes wird bei einem neuen Kinddatensatz automatisch in das gebundene Kindfeld übernommen.

Standard: Das gebundene Kindfeld ist schreibgeschützt. Die Einstellung boundFieldReadonly hat deshalb den Vorgabewert true.

Beispiel

ed_ev.id = 9201
        ↓
ed_ev_info.to_ev_id = 9201

Beim neuen Kinddatensatz darf nicht „Eltern-Datensatz wählen“ erscheinen. Der Wert ist bereits durch den aktuellen Hauptdatensatz bestimmt.

Designer-Einstellungen

EinstellungDefaultBedeutung
inheritParentValuetrueVerbindlich. Der Parent-Wert wird als Child-Wert übernommen.
boundFieldReadonlytrueBestimmt, ob der vorbelegte Child-Wert vom Benutzer geändert werden darf.

Read-only = true

Parent-ID:        9201
Child to_ev_id:   9201
Änderbar:         nein

Der Server erzwingt den Wert erneut. Selbst ein manipulierter Browser-Request kann dadurch keinen abweichenden Fremdschlüssel speichern.

Read-only = false

Parent-ID:        9201
Initialwert:      9201
Änderbar:         ja

Der Benutzer darf den Datensatz bewusst einem anderen Parent zuordnen. Nach dem Speichern kann er deshalb aus der aktuellen, auf 9201 gefilterten Kindansicht verschwinden.

Noch nicht gespeicherter Parent

Besitzt der Hauptdatensatz noch keine ID, darf kein persistenter Kinddatensatz angelegt werden. Der New-Record-Button des Child-Recordsets wird deaktiviert und erhält den Hinweis „Hauptdatensatz zuerst speichern“.

dataformContext

{
  "relations": {
    "parent": {
      "recordsetId": "rs_ed_ev",
      "keyField": "id",
      "keyValue": 9201,
      "childRecordsetId": "rs_ed_ev_info",
      "childField": "to_ev_id",
      "binding": {
        "inherited": true,
        "readonly": true
      }
    }
  }
}
